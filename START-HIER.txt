PageCollector 0.2
=================

AUS DEM REPOSITORY STARTEN

1. Unter Windows ein .NET-10-SDK installieren und PageCollector.sln öffnen.
2. In PowerShell im Repo: .\Verify.ps1
3. Danach eine Publish-Variante wählen:
   .\Build.ps1 -Publish                 (framework-dependent)
   .\Build.ps1 -Publish -SelfContained  (mit .NET-Runtime)
4. PageCollector.exe im passenden Ausgabeordner starten:
   dist\win-x64 bzw. dist\win-x64_self-contained.
   Start.cmd bevorzugt dist\win-x64 und nutzt sonst die zweite Variante.

Alternativ das Artefakt PageCollector-win-x64-self-contained aus einem erfolgreichen
GitHub-Actions-Lauf vollständig entpacken und PageCollector.exe starten.
Zum Funktionstest „Demo laden“, danach „Starten“ wählen.

Das Programm übernimmt die vorhandenen Einstellungen aus Version 0.1.
NEU: Automatik und Seitentitel im Dateinamen sind standardmäßig aktiv.
Der Automatiklauf öffnet keine Vorschau und verlangt keine Bestätigung.
Gespeicherte Dateien lassen sich per Doppelklick in der Ergebnisliste öffnen.

Edge oder Chrome muss installiert sein. Self-contained enthält die .NET-Runtime.
Die kleinere Variante PageCollector-win-x64-framework-dependent benötigt die
.NET 10 Desktop Runtime für Windows x64. Für den Quelltext wird das SDK benötigt.
Die bereits heruntergeladene Speicherhilfe wird wiederverwendet; sonst wird
die neueste stabile Windows-Version von SingleFile geladen.

Wie bei FileScope ist -Publish jetzt framework-dependent. Für die bisherige
Variante mit Runtime zusätzlich -SelfContained angeben. Die beiden Pakete in
getrennte Ordner entpacken. Ein Publish leert nur seinen eigenen Ausgabeordner.

SPEICHERHILFE VERWALTEN

Im Reiter „4. Speicherhilfe“ wird die offizielle Versionsliste geladen.
Standard ist „Neueste stabile Version“. Alternativ eine konkrete ältere
Version wählen und „Installieren / aktivieren“ anklicken. Eine erfolgreich
aktivierte ältere Auswahl bleibt auch nach einem Neustart erhalten.
Das bloße Auswählen oder Prüfen der Liste ändert die aktive Version noch nicht.

„Versionen prüfen“ aktualisiert die Liste. „Aktive Speicherhilfe“ zeigt die
Version für die nächsten Aufnahmen. Updates werden ausdrücklich aktiviert;
die App arbeitet bis dahin mit der bisherigen Version weiter. „Neueste“
bezieht sich auf die zuletzt erfolgreich geladene Liste.

„Ordner öffnen“ führt zu %LOCALAPPDATA%\PageCollector\tools.
Dort liegen single-file-<Version>.exe und engine.json für die Verwaltung.
Alte Installationen bleiben erhalten und können über die Liste wieder aktiviert
werden, auch ohne Internet. Vor jeder Verwendung wird die Prüfsumme geprüft.
Ein fehlgeschlagener oder abgebrochener Download ändert die aktive Auswahl nicht.

Vorhandene Installationen der Version 2.26.0 werden übernommen. Neue
Installationen brauchen Internet für Versionsliste und Download. Die Liste
enthält stabile Windows-Releases mit veröffentlichter SHA-256-Prüfsumme.
Während eines Sammellaufs ist ein Versionswechsel gesperrt.

SUCHWERTE UND URL-VORLAGEN

Ein Wert und eine URL-Vorlage pro Zeile. Vorlagen werden von oben nach unten
versucht. Für den Wert 123456 funktionieren beispielsweise:

  {id}                       -> 123456
  {id:1-3}                   -> 123
  {id:1,2,3}                 -> 123
  {id:4}                     -> 4
  {id:5-6}                   -> 56
  {id:1-3}/{id:4}/{id:5-6}    -> 123/4/56
  {id:1-3}/{id}              -> 123/123456

Gezählt wird ab 1, Bereiche schließen beide Endpunkte ein. {Suchwert}
funktioniert genauso. Groß-/Kleinschreibung ist bei Platzhaltern egal.
Die Beispiele sind URL-Bausteine: vollständige echte HTTP(S)-Adressen eintragen.
Zu kurze Werte oder ungültige Positionen werden bereits vor dem Start gemeldet.

AUTOMATIK UND AUSSCHLUSSTITEL

Im zweiten Reiter stehen standardmäßig diese zwei Zeilen:

  ^Wayback Machine
  404

^ bedeutet „Titel beginnt mit“. Ohne ^ muss der Text irgendwo im Titel
vorkommen. Groß-/Kleinschreibung ist egal. Weitere Zeichen sind wörtlich gemeint;
es sind keine regulären Ausdrücke. Eigene Ausschlüsse sind z.B.:

  nicht gefunden
  ^Access Denied

Solche allgemeinen Begriffe können auch nützliche Artikel ausschließen.
Auch 404 trifft jede Erwähnung, z.B. KB123404. Passe die Liste bei Bedarf an.
Geprüft wird der vollständige Seitentitel, nicht nur der gekürzte Dateiname.

Ausgeschlossener/fehlender Titel oder Aufnahmefehler -> nächste URL.
Erster gespeicherter Treffer -> nächster Suchwert, wieder bei Vorlage 1.
Alle Vorlagen erfolglos -> „Kein Treffer“, danach nächster Suchwert.
Schreibfehler im Ausgabeordner -> Lauf stoppt.
„Abbrechen“ stoppt den Lauf; bereits gespeicherte Seiten bleiben erhalten.

Die App prüft keine Fehlertexte im Seiteninhalt. Eine Fehlerseite mit einem
unauffälligen Titel kann gespeichert werden und braucht eine spätere Sichtung.
Ein HTTP-404-Status wird nicht separat geprüft; 404 wird im Titel gesucht.

DATEINAMEN

Im dritten Reiter lassen sich Präfix, Suffix und Seitentitel einstellen:

  Präfix + Suchwert + Suffix - Seitentitel.html

Beispiel: Präfix KB, Suchwert 123456, Suffix _DEU:

  KB123456_DEU - Installation des Updates.html

Präfix/Suffix enthalten genau deine Zeichen; _ oder Leerzeichen selbst ergänzen.
Der Titel wird auf höchstens 100 Zeichen an einer Wortgrenze gekürzt.
Ein einzelnes überlanges Wort wird nötigenfalls abgeschnitten. Ungültige
Windows-Dateizeichen werden ersetzt. Bei sehr langen übrigen Bestandteilen
kann der Titel kürzer werden, damit der gesamte Dateiname passt.

Der vollständige Titel bleibt in den Herkunftsangaben (.source.json) erhalten.
Die HTML-Kopie selbst bleibt unverändert. Vorhandene Dateien werden nie
überschrieben: Bei Namensgleichheit wird (2), (3) usw. angehängt.

MANUELLER MODUS

Im zweiten Reiter „Automatisch speichern und weiterlaufen“ abwählen.
Dann erscheinen die bisherigen Schaltflächen für Vorschau, Übernehmen,
nächste URL, Wiederholen und Überspringen. Ausschlüsse werden als Hinweis
angezeigt; die Übernahme entscheidest du in diesem Modus selbst.

PROTOKOLL UND PRÜFUNG

Im Ausgabeordner liegen HTML-Dateien, jeweils eine .source.json und ein
CSV-Protokoll (Semikolon, UTF-8) mit Versuchen und Ergebnissen.
Nach einem Abbruch können die fehlenden Werte anhand des Protokolls erneut
gesammelt werden. Es gibt noch kein automatisches Fortsetzen.

Build und automatisierte Prüfungen sind dokumentiert in TEST-REPORT.md.
Die CI prüft Build, MSTest-Tests und WPF-Bindings unter Windows. Echte
Edge-/Chrome-Aufnahmen sind separate, optionale Integrationstests. Ein
praktischer Test mit deinen Zielseiten bleibt sinnvoll.

Vollständiger C#-Quelltext und englische README sind enthalten.
